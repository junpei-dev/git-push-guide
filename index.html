プログラミング技術 ・ デプロイ編

はじめての git push

作ったアプリを GitHub に送るまでの手順です。上から順番に進めてください。コマンドは「コピー」を押して、ターミナルに貼り付けて Enter で実行します。

  1. 手順 1GitHub でリポジトリを作る
  2. 手順 2Kiro で準備する
  3. 手順 3〜5コマンドで GitHub に送る
  4. このあとCloudflare でつなぐ

はじめる前にこの PC で1回だけ

git に「だれが記録したか」を教えておく設定です。まず次のコマンドで、設定済みか確かめます。

PS C:\…>
名前が表示されたら

設定済みです。このボックスは飛ばして手順1へ。何も出なければ、下の2つを設定します。

GitHub の右上のアイコン → Settings → Emails の「Keep my email addresses private」の説明の中にあります。自分のメールアドレスを公開しないために、こちらを使います。
PS C:\…>
PS C:\…>
こうなれば成功

どちらも何も表示されなければ設定できています。

1

GitHub でリポジトリを作る

  1. ブラウザで GitHub を開き、右上の「+」→「New repository」
  2. Repository name は半角の小文字・数字・ハイフン（-）だけで付ける。例：my-quiz-app
  3. Public / Private は先生の指示どおりにする
  4. README・.gitignore・ライセンスは追加しない（初めの状態のまま）で「Create repository」
  5. 次の画面で「HTTPS」を選び、表示された URL をコピーして下に貼る
注意　README などを追加して作ると、手順4の最後で送れなくなります（「困ったとき」の rejected を参照）。

まだ貼られていません。GitHub の画面で HTTPS の URL をコピーして貼ってください。

2

Kiro で準備する

  1. Kiro でアプリのフォルダを開く
  2. 新しいチャットを開き、先生が配った デプロイ用プロンプト.txt の中身を貼る
  3. 1行目の「リポジトリ名：」の後ろを に書き換えてから送信する
  4. Kiro が wrangler.jsonc と .gitignore を作り終わるまで待つ
  5. 最後に Kiro が教えてくれる「ビルドコマンド」と「デプロイコマンド」をメモしておく（Cloudflare で使う）
なぜ先に Kiro？　wrangler.jsonc が入っていない状態で送ると、Cloudflare でのデプロイが必ず失敗します。送る前にそろえておきます。
3

ターミナルを開く

  1. Kiro のメニューの「ターミナル」→「新しいターミナル」
  2. 画面の下に出た行の最後が、アプリのフォルダ名になっているか確かめる
こうなっていれば OK（my-quiz-app の部分が自分のフォルダ名）
PS C:\Users\…\my-quiz-app>

違うフォルダ名が出ていたら、Kiro でアプリのフォルダを開き直してから、もう一度ターミナルを開きます。

4

コマンドで GitHub に送る

7つのコマンドを、上から1つずつ実行します。1つ打つたびに、表示が「こうなれば成功」と同じか確かめてから次へ進みます。

4-1

このフォルダを git で管理し始める

PS C:\…>
こうなれば成功

全部のファイルを「送る候補」に入れる。最後の .（ピリオド）を忘れない

warning（注意）は何行出ても、まったく出なくても問題ありません。

5

GitHub で確かめる

  1. ブラウザの GitHub のページを再読み込みする
  2. ファイルの一覧が表示されていれば完了
  3. wrangler.jsonc と .gitignore がある、node_modules がないことを確かめる

このあと：Cloudflare でつなぐ

Cloudflare の「アプリケーションを作成する」→「Continue with GitHub」で、このリポジトリを選びます。設定の画面では、次のように入力します。

項目素の HTML のアプリVite で作ったアプリ
ビルドコマンド空欄npm run build
デプロイコマンドnpx wrangler deploy
最初から入っている。変えない		npx wrangler deploy
最初から入っている。変えない
ルートディレクトリ空欄空欄

迷ったら、手順2で Kiro が教えてくれたコマンドを入れます。

2回目から（アプリを直したとき）

手順1〜3と 4-1・4-5・4-6 はもう要りません。直したら、この3つだけです。コミットは貼り付けたあと、" " の中を「何を直したか」に書き換えてから Enter を押します。

PS C:\…>
PS C:\…>
PS C:\…>

プッシュすると、Cloudflare が自動でアプリを作り直します。公開ページに反映されるまで数分かかります。

困ったとき

ターミナルに出た英語の中から、下と同じ文を探してください。出てくる順に並んでいます。

  • warning: … LF will be replaced by CRLF …4-2 ・ 心配なし
    原因
    Windows と Mac で改行の書き方が違うのを、git が自動で調整しているお知らせです。
    直し方
    何もしなくて大丈夫です。そのまま次へ進みます。
  • git status に node_modules や .env が出てきた4-3
    原因
    .gitignore がない、または中身が足りません。
    直し方
    Kiro に「.gitignore を直して」と頼みます。直ったら、次の2つを順に実行して候補を入れ直します。
    PS C:\…>
    PS C:\…>
  • Author identity unknown
    *** Please tell me who you are.    4-4
    原因
    「はじめる前に」の設定がまだです。
    直し方
    ページ上の「はじめる前に」を済ませてから、4-4 をもう一度実行します。
  • 黒い画面に切り替わって、戻れない4-4
    原因
    -m "…" を付けずにコミットしたので、メッセージを書く画面（vim）が開きました。
    直し方
    入力を半角にしてから Esc を押し、:q! と打って Enter。元の画面に戻ったら、4-4 をコピーしてやり直します。
  • error: remote origin already exists.4-6
    原因
    送り先はもう登録されています（4-6 を2回実行した、など）。
    直し方
    次のコマンドで、送り先を手順1の URL に上書きします。
    PS C:\…>
  • error: src refspec main does not match any4-7
    原因
    コミットができていません。
    直し方
    4-2（git add .）と 4-4（git commit）をやり直してから、4-5 → 4-7 と進みます。
  • ! [rejected] main -> main (fetch first)4-7
    原因
    手順1でリポジトリを作るときに、README などを追加しました。
    直し方
    作ったばかりのリポジトリのときだけ、次のコマンドで上書きして送れます。それ以外のときには使いません。
    PS C:\…>
  • remote: Repository not found.4-7
    原因
    URL が間違っているか、ブラウザで別の GitHub アカウントにログインしています。
    直し方
    手順1の URL を GitHub の画面と見比べ、違っていたら貼り直して「remote origin already exists」の直し方で上書きします。それでも出るときは先生を呼んでください。

このページのコマンドと表示は、Git for Windows 2.54 と PowerShell 5.1（Kiro のターミナル）で確認したものです。
